# .su3ds とは

[READMEへ戻る](../README.md)

`.su3ds` は、3DGS_Su が読み込むための独自形式です。
PLY / SOG の 3DGS データから、AviUtl2 で描画するのに必要な情報だけを
抜き出した **固定長のバイナリファイル** で、一般的な 3DGS ビューアでは開けません。

## ファイルの中身

- 先頭40バイトのヘッダ
  - `SU3DGS` の識別子、バージョン、点数、点群の範囲
- 以降は1点40バイトのレコード
  - 位置 3×float32（12バイト）
  - 描画用の共分散 6×float32（24バイト）
  - 色 16ビット（512色）
  - 不透明度 8ビット（8段階）
  - 予約 1バイト
- 30,000点で約1.2MB
- 点は不透明度が高い順に間引かれ、指定した上限まで保存される
- 変換時に同名の `.json` が作られ、元ファイル、元の点数、範囲などが残る

色は3ビット×3チャンネルの512色、不透明度は8段階です。
視点依存のSH色は持たず、PLY / SOG のDC成分だけを使います。

## なぜ PLY / SOG を直接使わないのか

PLY / SOG は、位置・回転・スケール・不透明度・色（SH）を
点ごとに持つため巨大です。90,000点のPLYが約21MB、SOGでも数MBあり、
数百万点になるとLuaが毎フレーム読み直して描画するには大きすぎます。

`.su3ds` は、その変換を一度だけ行っておくためのキャッシュです。
描画に必要な形に整えてあるので、読み込み後は直接参照でき、
毎フレームの処理は深度順の並べ替えと描画だけになります。
元のPLY / SOGを毎回変換する必要はなく、一度作れば使い回せます。

## SuperSplat などのビューアとの違い

SuperSplatはGPUで元の点群をそのまま描きます。
200万点を間引かず、floatのまま載せ、画面空間でガウシアンの広がりを評価し、
毎フレーム深度ソートし、視点依存のSH色も使います。

一方、3DGS_SuはAviUtl2の `drawpoly` で四角形を並べる方式です。
GPUの点群バッファを直接読むAPIがないため、`.su3ds` では
表示点数を減らし、色と不透明度を量子化し、簡易的な深度順で描画します。
既定の30,000点は軽さを優先した値で、`表示上限` を上げれば密度は増えますが、
SuperSplatと同じ画質にはなりません。
